# RiskLens：面向股票与 ETF 组合的确定性风险分析与假设压力测试系统

*——一种将数值计算与自然语言交互分离的全栈实现*

**作者：** Tian Lu  
**项目类型：** 量化金融 / 运筹学 / 全栈软件工程  
**版本：** Phase 1–3  
**日期：** 2026 年 10 月

---

## 摘要

个人投资者与研究人员通常能够观察投资组合的名义权重，却难以快速判断波动风险由哪些资产驱动、资产间相关性是否削弱了分散效果，以及组合在市场、行业和利率冲击下可能出现的损失。与此同时，将大语言模型直接用于金融数值计算会引入数值幻觉、不可复现以及结果来源不透明等问题。针对上述问题，本文设计并实现了 RiskLens——一个面向股票与交易型开放式指数基金组合的确定性风险分析与假设压力测试系统。

系统采用前后端分离架构。后端基于 Python、FastAPI、Pydantic、pandas 与 NumPy，从 Yahoo Finance 历史日线数据构建对齐收益率序列，并计算年化收益率、年化波动率、Sharpe 比率、历史风险价值、条件风险价值、回撤、相关性、集中度及 Euler 波动风险贡献。压力测试模块支持广义市场、科技行业、利率及单一证券四类冲击，并返回组合收益、美元损益、资产归因、风险因子归因及模型假设。前端使用 React、TypeScript、Tailwind CSS 与 Recharts 构建桌面端风险终端。

为保证数值可控性，Risk Officer 不独立计算金融指标。当前生产版本采用零成本确定性规则引擎，将受控的中英文情景描述转换为结构化参数，再调用 Python 压力测试引擎；自然语言层仅选择解释模板与证据字段。系统通过三十五项自动化测试验证输入约束、数值公式、风险贡献守恒、压力损益一致性、利率冲击方向及接口异常处理。本项目展示了将自然语言解释层与确定性数值引擎严格分离的可行性，从而在保持交互性的同时增强金融分析系统的可复现性、可审计性与部署可控性。

**关键词：** 投资组合风险；风险价值；条件风险价值；压力测试；风险贡献；FastAPI；确定性计算；自然语言交互

## 1. 引言

现代投资组合分析不仅关注预期收益，还需要评估波动性、尾部损失、资产间依赖关系以及风险来源。Markowitz 均值—方差框架奠定了以协方差矩阵描述组合风险的基础，但仅展示组合波动率并不能回答以下问题：

1. 哪一项资产贡献了最多风险；
2. 名义持仓数量是否真实反映分散程度；
3. 历史尾部亏损是否显著大于普通波动；
4. 市场、科技板块或利率变化如何传导至组合；
5. 如何以自然语言解释结果，同时避免语言模型虚构金融数值。

RiskLens 的目标不是预测证券价格或提供个性化投资建议，而是构建一个透明、模块化且可复现的研究型风险终端。系统遵循三项核心原则：

- **数值确定性：** 所有金融指标和情景损益均由 Python 代码计算；
- **来源透明性：** 明确区分历史统计、模型假设与假设情景结果；
- **解释与计算分离：** 自然语言层可以解释和路由，但不能成为数值来源。

本文的主要贡献包括：

1. 构建覆盖收益、波动、尾部风险、回撤、相关性、集中度和风险贡献的统一计算管线；
2. 设计支持四类冲击及资产和因子双重归因的确定性压力测试引擎；
3. 实现不依赖付费模型的中英文受控情景解析与证据化风险解释；
4. 通过类型化接口、自动化测试、容器化和云部署形成可复现的全栈系统。

## 2. 问题定义与系统边界

设投资组合包含 \(n\) 项资产，权重向量为：

\[
w = [w_1,w_2,\ldots,w_n]^\top,
\qquad \sum_{i=1}^{n} w_i = 1,
\qquad w_i \ge 0.
\]

当前系统面向多头、完全投资的股票与 ETF 组合。用户输入证券代码、组合权重以及可选组合价值。系统输出历史风险指标和假设压力结果，但不执行交易、不预测未来价格，也不推荐买入或卖出。

RiskLens 将信息分为三类：

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| 历史统计 | 根据已获取的历史价格计算 | 历史波动率、VaR、最大回撤 |
| 模型假设 | 压力模型使用的公开近似 | TLT 久期假设、SPY 科技暴露假设 |
| 假设结果 | 对用户指定冲击的敏感性估计 | 科技下跌与利率上升情景损失 |

该分类用于防止用户将历史估计或线性压力结果误认为预测。

RiskLens 采用前后端分离与分层模块化设计：

```text
用户输入组合
      ↓
React / TypeScript 前端
      ↓ 类型化 JSON
FastAPI + Pydantic API
      ↓
MarketDataProvider 市场数据层
      ↓
Yahoo Finance 历史价格
      ↓
日期对齐与日收益率计算
      ↓
确定性 Python 风险引擎
      ├── 收益与波动率
      ├── VaR / CVaR
      ├── 回撤与相关性
      ├── 集中度与风险贡献
      └── 压力测试与损益归因
      ↓
确定性 Risk Officer
      ├── 受控中英文情景解析
      └── 基于证据的解释模板
```

后端主要接口如下：

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| `GET` | `/health` | 服务健康检查 |
| `GET` | `/market/history/{ticker}` | 单项资产历史数据 |
| `POST` | `/portfolio/analyze` | 组合历史风险分析 |
| `POST` | `/portfolio/stress-test` | 结构化压力测试 |

## 4. 投资组合风险方法

### 4.1 日收益与组合收益

资产 \(i\) 在交易日 \(t\) 的简单收益率为：

\[
r_{i,t}=\frac{P_{i,t}}{P_{i,t-1}}-1.
\]

令 \(r_t\) 为当日资产收益向量，则组合日收益为：

\[
r_{p,t}=w^\top r_t.
\]

系统按共同交易日期对齐价格序列并处理缺失值，避免因不同上市日期或停牌造成向量错位。

### 4.2 年化收益率

系统使用几何复合方式估计年化收益率：

\[
R_{ann}=\left(\prod_{t=1}^{T}(1+r_{p,t})\right)^{252/T}-1.
\]

其中 \(T\) 为有效交易日数量，252 为近似年交易日数。

### 4.3 年化波动率

日收益协方差矩阵为：

\[
\Sigma=\operatorname{Cov}(r).
\]

年化协方差及组合波动率分别为：

\[
\Sigma_{ann}=252\Sigma,
\qquad
\sigma_p=\sqrt{w^\top\Sigma_{ann}w}.
\]

系统对零波动和奇异协方差等边界情况进行显式处理，而不是返回无穷值或使接口崩溃。

### 4.4 Sharpe 比率

给定可配置的年化无风险利率 \(R_f\)，系统计算：

\[
S=\frac{R_{ann}-R_f}{\sigma_p}.
\]

该结果被标记为基于历史样本的年化估计，不代表未来风险调整收益。

### 4.5 历史 VaR 与 CVaR

在置信水平 \(\alpha\) 下，历史风险价值采用正损失展示约定：

\[
VaR_{\alpha}=-Q_{1-\alpha}(r_p).
\]

条件风险价值，又称期望损失，为：

\[
CVaR_{\alpha}
=-E\left[r_p\mid r_p\le Q_{1-\alpha}(r_p)\right].
\]

系统默认展示百分之九十五置信水平的一日 VaR 与 CVaR。VaR 描述历史损失阈值，而 CVaR 描述越过该阈值后的平均损失。

### 4.6 回撤

组合累计财富曲线定义为：

\[
V_t=\prod_{i=1}^{t}(1+r_{p,i}).
\]

运行最高点与回撤分别为：

\[
M_t=\max_{s\le t}V_s,
\qquad
DD_t=\frac{V_t}{M_t}-1.
\]

最大回撤为：

\[
MDD=\min_t DD_t.
\]

实现中将初始财富纳入高水位，以正确处理样本起始阶段立即亏损的情形。

### 4.7 相关性分析

系统根据对齐后的资产日收益计算 Pearson 相关系数矩阵，并排除对角线上的自相关，输出相关性最高的资产对。相关性超过固定阈值时，由独立规则引擎触发风险标志，而不是由自然语言层自由判断。

### 4.8 波动风险贡献

资产 \(i\) 的边际风险贡献为：

\[
MCR_i=\frac{(\Sigma_{ann}w)_i}{\sigma_p}.
\]

绝对风险贡献为：

\[
CR_i=w_iMCR_i.
\]

百分比风险贡献为：

\[
PCR_i=\frac{CR_i}{\sigma_p}.
\]

根据 Euler 分解，应满足：

\[
\sum_{i=1}^{n}PCR_i\approx 1.
\]

系统通过自动化测试检查该守恒关系，使用户能够比较“资本权重”与“风险权重”的差异。

### 4.9 集中度

Herfindahl–Hirschman 指数定义为：

\[
HHI=\sum_{i=1}^{n}w_i^2.
\]

有效持仓数量为：

\[
N_{eff}=\frac{1}{HHI}.
\]

与单纯持仓数量相比，\(N_{eff}\) 能够更准确地反映权重集中程度。系统同时报告最大单项权重和前三大持仓合计权重。

## 5. 压力测试模型

### 5.1 情景类型

系统支持以下四类结构化冲击：

1. 广义市场百分比冲击；
2. 科技行业百分比冲击；
3. 利率基点冲击；
4. 单一证券百分比冲击。

系统还提供四个历史风格预设：金融危机风格、疫情崩盘风格、利率冲击风格与科技抛售风格。预设仅是简化的假设情景，不声称精确复现历史事件。

### 5.2 资产与组合损益

对资产 \(i\)，压力贡献为：

\[
\Delta V_i=w_i\times shock_i.
\]

组合压力收益为：

\[
\Delta V_p=\sum_i w_i shock_i.
\]

若用户提供组合价值 \(V_0\)，则：

\[
PnL=V_0\Delta V_p,
\qquad
V_1=V_0(1+\Delta V_p).
\]

系统同时返回资产级贡献和风险因子级贡献，并检查二者与组合总压力结果一致。

### 5.3 利率冲击

对静态映射中的债券 ETF，系统使用一阶久期近似：

\[
\frac{\Delta P}{P}\approx-D\Delta y.
\]

其中 \(D\) 为有效久期假设，\(\Delta y\) 为收益率变化。例如，TLT 使用十六年的备用久期假设。当利率上升一百个基点时，其一阶价格冲击约为负百分之十六。

该方法忽略凸性、信用利差、流动性和非线性效应，因此所有久期数值都在界面中标记为“备用建模假设”，而非实时市场数据。

### 5.4 科技暴露假设

系统对常见科技股票使用静态分类，对宽基 ETF 使用部分行业暴露假设。例如，SPY 的科技暴露采用百分之三十的备用值。该参数仅用于假设压力测试，不能被解释为实时持仓披露。

### 5.5 单一证券覆盖规则

若用户指定单一证券冲击，该冲击被视为该证券的总压力收益，并覆盖其市场、行业和利率聚合结果，而不是在已有因子冲击上重复叠加。该规则可防止同一资产被重复冲击。

## 6. Risk Officer 的数值控制边界

### 6.1 设计动机

通用语言模型能够改善交互体验，但不适合作为投资组合指标的权威计算来源。RiskLens 因此实施以下控制边界：

- 自然语言层不得生成或修改金融指标；
- 所有展示数值必须来自 Python 结果或用户显式输入；
- 情景参数必须经过 Pydantic 再验证；
- 无法安全解析的情景必须被拒绝，而不是猜测；
- 解释必须区分历史统计、模型假设和假设结果；
- 系统不得提供买卖建议。

### 6.2 当前生产实现

当前生产版本使用零成本确定性 Risk Officer，不依赖外部付费模型。其处理过程为：

```text
用户自然语言
      ↓
受控中英文词典与情景语法
      ↓
Pydantic 结构化情景
      ↓
Python 压力测试引擎
      ↓
确定性数值结果
      ↓
规则排序与解释模板
      ↓
附带来源标签的自然语言简报
```

解析器支持含明确数字的常见中英文表达，例如科技板块下跌、市场下跌、利率上升或组合内证券下跌。复杂、含糊或未覆盖的表达会提示用户改用结构化压力测试面板。

系统保留可选的 OpenAI 适配器，但默认配置为 `AI_PROVIDER=deterministic`。即使启用可选模型模式，模型也只能解析意图、选择证据和生成定性文本，不能计算最终损益。

## 7. 数据、前端与部署

### 7.1 市场数据

MVP 通过 yfinance 获取 Yahoo Finance 调整后历史日线价格。“LIVE DATA”表示后端在用户点击分析时获取了最新可用的历史日线数据，不代表秒级实时行情或交易所直连报价。

数据层处理以下问题：

- 无效证券代码；
- 无价格历史；
- 新上市证券导致的短样本；
- 不一致交易日期；
- 缺失观测；
- 网络失败；
- 零波动与协方差退化。

### 7.2 前端交互

前端采用深色专业终端风格，并提供：

- 投资组合编辑与权重归一化；
- 风险指标总览；
- 相关性热力表；
- 风险贡献对比；
- 回撤曲线；
- 集中度和规则化风险标志；
- 压力情景输入与损益归因；
- 确定性 Risk Officer。

页面初始状态显示固定演示快照。只有用户点击分析、后端成功返回 Yahoo Finance 数据后，状态才切换为 `LIVE DATA`，从而避免将静态演示数据伪装成实时分析。

### 7.3 部署

后端以 Docker 容器部署在 Railway，前端部署为私有 Sites 项目。浏览器通过 HTTPS 调用 FastAPI，后端使用 CORS 白名单限制允许的前端来源。生产环境不保存 OpenAI API Key，Risk Officer 使用确定性模式运行。

- 缺少付费 API Key 时确定性模式仍可运行；

默认组合为：

| --- | ---: |

| MSFT | 20% |

### 8.3 假设案例

考虑以下用户情景：

> 科技板块下跌 15%，利率上升 100 个基点。

对科技股票采用完全科技暴露，对 SPY 采用百分之三十科技暴露，对 TLT 采用十六年久期假设。线性计算如下：

| 证券 | 权重 | 估计资产冲击 | 组合贡献 |
| --- | ---: | ---: | ---: |
| AAPL | 20% | -15.00% | -3.000% |
| MSFT | 20% | -15.00% | -3.000% |
| NVDA | 15% | -15.00% | -2.250% |
| SPY | 25% | -4.50% | -1.125% |
| TLT | 20% | -16.00% | -3.200% |
| **合计** | **100%** | — | **-12.575%** |

若组合初始价值为 100,000 美元，则估计损益为：

\[
100{,}000\times(-0.12575)=-12{,}575.
\]

压力后组合价值约为 87,425 美元。该结果是由显式输入和静态暴露假设产生的线性敏感性估计，不是市场预测，也不包含波动率跳升、流动性恶化、相关性收敛或二阶效应。

## 9. 系统局限性

RiskLens 当前版本存在以下限制：

1. Yahoo Finance 数据适合研究与演示，不构成交易所级实时数据源；
2. 历史风险指标依赖样本窗口，不能直接预测未来分布；
3. 压力测试采用线性加总，忽略凸性、期权性、流动性、信用利差及相关性反馈；
4. 科技暴露和债券久期使用静态备用映射，并非实时基金持仓或风险数据；
5. 当前尚未实现 Fama–French 因子回归和组合优化；
6. 受控语言解析器不具备通用对话模型的开放语义覆盖能力；
7. 当前组合约束为多头和完全投资，未覆盖杠杆、卖空、衍生品和外汇风险；
8. 系统未计入交易成本、税费、市场冲击与再平衡约束；
9. 项目属于研究型风险分析工具，不应宣称机构级定价或风险管理准确性。

## 10. 后续研究方向

后续开发可以沿以下方向展开：

- 基于 SPY 的市场 Beta 与 Fama–French 多因子回归；
- 使用 cvxpy 实现最小波动率、最大 Sharpe 和风险平价比较；
- 引入 PostgreSQL 或 Supabase 保存投资组合与分析历史；
- 接入更稳定的机构型行情与基金持仓数据源；
- 使用实时 ETF 行业权重与久期数据替代静态假设；
- 加入波动率冲击、相关性冲击和流动性折价；
- 扩展期权、外汇、信用产品和多币种风险；
- 增加身份验证、监控、审计日志及部署成本控制；
- 建立滚动样本、回测和模型稳定性评估框架。

## 11. 结论

本文设计并实现了一个覆盖投资组合历史风险、风险来源和假设压力分析的全栈系统。RiskLens 的核心价值不在于预测市场，而在于将复杂的组合风险转换为可追溯的数值、归因结果和明确标注的模型假设。

项目证明，自然语言交互并不要求将金融计算交给语言模型。通过把意图解析、数值计算和结果解释拆分为独立层，可以让 Python 成为唯一数值权威，同时保留面向非专业用户的自然语言入口。当前确定性生产模式进一步降低了运行费用和外部服务依赖，并增强了结果的可复现性。

因此，RiskLens 可作为量化金融、运筹学、数据工程和全栈软件工程交叉方向的研究型项目基础。其架构可以继续扩展因子模型与约束优化，但所有扩展仍应保持相同原则：金融数值必须可验证，模型假设必须可见，语言解释不得替代计算证据。
